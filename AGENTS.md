# AGENTS.md — Duty Schedule App

Информационное табло графика дежурств. Flask-приложение читает Google-таблицу,
кэширует расписание в памяти, отдаёт его как JSON и рисует полноэкранный
kiosk/TV-дашборд на две рабочие недели. Параллельно фоновый воркер шлёт
напоминания в беседу VK.

Язык кода, логов и UI — русский. Держитесь его в новых сообщениях и комментариях.

---

## 1. Быстрый старт

Виртуальное окружение уже лежит в `.venv/` (Python 3.11+, Windows).

```bash
.venv/Scripts/python.exe -m unittest discover -s backend/tests -t backend -v
```

`-t backend` обязателен: он кладет `backend/` в `sys.path`, иначе не
резолвятся ни `duty_scheduler`, ни `tests.helpers`.

Локальный запуск (dev-сервер Flask, порт 5000):

```bash
LOG_DIR=logs VK_BOT_TOKEN= VK_PEER_ID= .venv/Scripts/python.exe backend/duty_app.py
```

`LOG_DIR=logs` и пустые VK-переменные — обязательная гигиена для локального
запуска, см. §6. Проверка живости:

```bash
curl -s http://localhost:5000/health
```

Прод-подобный запуск: `backend/serve.py` сам выбирает бэкенд — `waitress` на
Windows, `gunicorn -c gunicorn.conf.py wsgi:app` на POSIX (запускается с
`cwd=backend/`, чтобы gunicorn нашел `wsgi`).

Docker: `./deploy.sh` (интерактивно создаёт `.env`, проверяет `credentials.json`,
поднимает compose и ждёт `/health`) либо напрямую `docker compose up -d --build`.

## 2. Карта репозитория

Репозиторий разделен на три зоны: `backend/` — весь Python, `frontend/` — всё,
что отдается браузеру, корень — деплой и рантайм-секреты. Это разделение
используется CI для условной сборки, см. §11.

```
backend/     весь Python: приложение, точки входа, тесты, зависимости
frontend/    templates/ + static/, сборки нет (vanilla JS; Bootstrap с CDN — только на /settings)
корень       Dockerfile, docker-compose.yml, deploy.sh + .env (в git не хранится);
```

### Как разрешаются пути

`AppConfig.project_root` = `parents[2]` от `config.py`, то есть корень репозитория
локально и `/app` в контейнере. От него отсчитываются `credentials.json` и
`vk_users.json`. Шаблоны и статика берутся из `AppConfig.frontend_dir`
(`project_root/frontend`, переопределяется через `FRONTEND_DIR`).

`duty_app.py` запускается как `python backend/duty_app.py` — Python сам кладет
каталог скрипта в `sys.path`. Gunicorn запускается с `cwd=backend/` и по
умолчанию добавляет рабочий каталог в `sys.path`, поэтому `wsgi:app`
резолвится. Не переносите точки входа из `backend/`, не поправив это.

Версия приложения захардкожена: `AppConfig.app_version = "2.7.0"` в
[config.py](backend/duty_scheduler/config.py). Она же прокидывается в `?v=` для
cache-busting статики в [index.html](frontend/templates/index.html:10). При изменении
фронтенда версию надо бампать, иначе на табло приедет старый CSS/JS.

## 3. Как работают данные

### Доступ

Сервисный аккаунт Google запрашивает единственный scope —
`https://www.googleapis.com/auth/spreadsheets.readonly`. Приложение только
читает; расширять scope не нужно и не следует.

### Источник

Один лист Google-таблицы: **«Новое Дежуство »** (да, с опечаткой в названии и
пробелом на конце), gid **1262048925**. Доступ — сервисный аккаунт из
`credentials.json`.

Лист выбирается **по gid**, а не по имени: `open_duty_worksheet()` сначала пробует
`DUTY_SHEET_GID`, и только если такого листа нет — ищет по `DUTY_SHEET_NAME`
(сравнение без учёта регистра и хвостовых пробелов). Так переименование листа не
ломает приложение.

В той же книге лежат легаси-листы «Вечернее дежурство», «Дежурство по утрам» и
«Дежурство по субботам» с данными за январь–июль 2026. Приложение их **больше не
читает**.

### Структура листа

Блоки по три строки, повторяющиеся сверху вниз:

```
      A        B       C       D       E       F        G           H         I
 1  Столбец 1  пн      вт      ср      чт      пт      Время        сб
 2  дата      31.08   01.09   02.09   03.09   04.09                05.09
 3  утро              Булатов Иван…   …                с 8:00 до 10:00  Козлов Егор…  с 8:00 до 16:00
 4  вечер             Афонин Кирилл…  …                с 17:00 до 20:00 Козлов Данила…
 5  дата      07.09   08.09   …
```

* Колонки **B–F** — ПН–ПТ, колонка **H** — суббота.
* Колонки **G** и **I** — подписи времени, колонка **L** — справочный список людей.
* Даты — короткие, `ДД.ММ`.

Парсер (`parse_duty_sheet`) **не зашивает номера колонок**. Он находит строки,
в которых есть хоть одна ячейка-дата, и для каждой такой строки берёт `+1` как
«утро» и `+2` как «вечер» (если следующая строка сама не является строкой дат —
так корректно обрабатывается последний блок, где подпись «вечер» в колонке A
потеряна). Колонки со временем и справочником отсеиваются сами: в строке дат у
них пусто, поэтому колонка просто не рассматривается. Добавят колонку или
сдвинут блок — парсер это переживёт.

Дубли дат схлопываются: запись за дату создаётся один раз, пустые поля
дозаполняются из последующих блоков.

### Суббота

По субботам смена одна — «с 8:00 до 16:00», но людей бывает двое, и в таблице
они разнесены по строкам «утро» и «вечер». Парсер **склеивает их в одно поле
`evening`** через запятую, а `morning` оставляет пустым. Так сделано потому, что
и фронтенд (`isWeekend` → показывает только `duty.evening`), и VK-нотифаер
(`field_name = "evening"` для субботы) уже читают именно `evening`. Легаси-лист
«Дежурство по субботам» хранил тех же двух человек в одной ячейке — семантика
сохранена.

### Год в датах

В таблице год не указан. `parse_date_cell(value, reference_date)` подбирает из
`год-1 / год / год+1` тот, при котором дата ближе всего к текущей. Это чинит
стык декабря и января: 29.12 и 04.01 в одном блоке больше не разъезжаются на год.

### Имена

В таблице — полные ФИО с отчеством («Козлов Данила Дмитриевич»).

**В кэше они хранятся целиком, а на табло уходят без отчества.**
`build_api_payload()` пропускает каждое имя через `shorten_name()`, который
отсекает слово, похожее на отчество, и только начиная с третьего — иначе
фамилия вида «Иванович» потерялась бы вместе с ним. Легаси-ячейка «Толстогузов
Никита Юртаев Дмитрий» (двое без отчеств) не обрезается.

VK-уведомления берут данные из кэша, поэтому в них остаются полные ФИО.
Менять это стоит осознанно: `split_duty_names()` опирается на отчества, когда
режет ячейку с несколькими дежурными без запятой.

`vk_users.json` хранит ключи из двух слов, а в таблице ФИО из трёх.
`VkNotifier.find_user_info()` ищет сначала по полному имени, потом по
«Фамилия Имя» — так работают оба формата. Файл маппинга менять не требуется.

### Пайплайн

```
_background_updater (поток, tick = 10 c)
  ├─ update_google_sheets()  каждые GOOGLE_UPDATE_INTERVAL (60 c)
  │    └─ open_duty_worksheet()  — лист по gid, фолбэк по имени
  │         └─ parse_duty_sheet()  — блоки дата/утро/вечер
  │              └─ data_cache["schedule"]
  └─ update_ntp_time()       каждые NTP_UPDATE_INTERVAL (60 c)
       └─ data_cache["ntp_time"] / ["ntp_last_sync"]
```

`data_cache` — обычный dict под `cache_lock`. Никакой БД нет; перезапуск = потеря
кэша и повторная загрузка на старте.

### Время

Приложение **не доверяет системным часам**: `get_current_datetime()` берёт
последнее NTP-время и прибавляет `time.time() - ntp_last_sync`. Список серверов
перебирается по очереди (`time.google.com` → … → `ntp2.stratum2.ru`); если не
ответил никто — фолбэк на `datetime.now(server_tz)`.

Это важно для уведомлений VK: они привязаны к точной минуте. Любое изменение в
`get_current_datetime()` напрямую влияет на то, отправятся ли напоминания.

### Отображаемое окно

`get_two_work_weeks()` строит ровно **2 недели × 6 дней (ПН–СБ)**. Воскресенье
исключено; если сегодня воскресенье, окно сдвигается на следующий понедельник.
Дни без записи в таблице всё равно попадают в вывод с пустыми полями — сетка
табло всегда полная.

## 4. HTTP API

| Метод | Ответ |
|---|---|
| `GET /` | HTML-табло |
| `GET /settings` | HTML-страница настроек (сама по себе пароля не спрашивает, см. §7) |
| `GET /api/data` | `{success, data: {...}, timestamp}` |
| `GET /health`, `GET /api/health` | `{status, ntp_synced, data_loaded, last_data_update, last_ntp_sync, timestamp}` |
| `GET /version` | `{version, timestamp}` |
| `GET /api/settings/session` | `{password_set, authenticated}` |
| `POST /api/settings/password` | задать пароль (первый раз) или сменить (`current_password`) |
| `POST /api/settings/login`, `POST /api/settings/logout` | вход и выход |
| `GET /api/settings`, `POST /api/settings` | чтение и запись значений, требуют входа |
| `GET /api/settings/vk-users`, `POST /api/settings/vk-users` | список участников VK и его замена целиком, требуют входа |
| `GET /api/settings/credentials`, `POST /api/settings/credentials` | статус ключа Google (без содержимого) и загрузка файла, требуют входа |

`data` из `/api/data`:

```json
{
  "today": "2026-09-02",
  "today_duty": {"morning": "...", "evening": "...", "date": "..."},
  "weeks": [[{"date":"2026-08-31","date_str":"31.08","weekday":"ПН","morning":"","evening":""}, ...6 шт], [...]],
  "error": null,
  "server_time": "2026-09-02T17:42:03.137514+05:00",
  "last_updated": 1788352908.74
}
```

`today_duty` = `null`, если на сегодня записи нет (фронтенд это поле уже не
читает, см. §8). `error` — строка последней ошибки обновления; кэш при ошибке
не сбрасывается, поэтому фронтенд при непустом `last_updated` продолжает
показывать данные и лишь подсвечивает строку состояния.
У данных дежурств аутентификации нет — приложение рассчитано на доверенную
локальную сеть. Пароль стоит только на настройках, см. §7.

Контракт payload'а зафиксирован тестом
[test_schedule_service.py](backend/tests/test_schedule_service.py) и разбирается в
`processData()` в [app.js](frontend/static/app.js:132). Меняете форму — правьте оба места.

## 5. Уведомления VK

`VkNotifier._notification_loop` крутится с `sleep(60)`; `check_upcoming_duties()`
сразу выходит, если минута не нулевая, и передаёт работу
`_send_notification()` — тот владеет ключом дедупликации, проверкой на пустое
дежурство и логированием.

| Когда | Тип | Поле | Текст |
|---|---|---|---|
| 10:00 в будни | `evening_today` | `evening` за сегодня | «Сегодня (03.09, ЧТ) вечером дежурит: …» |
| 10:00 в субботу | `saturday_today` | `evening` за сегодня | «В эту субботу (05.09) дежурят: …» |
| 19:00 накануне будня | `morning_tomorrow` | `morning` за завтра | «Завтра (04.09, ПТ) утром дежурит: …» |
| 19:00 в пятницу | `saturday_tomorrow` | `evening` за завтра | «В эту субботу (05.09) дежурят: …» |

Субботняя смена анонсируется **дважды** — вечером накануне и утром того же дня.
Ключи дедупликации у этих двух уведомлений разные, поэтому второе не глушится
первым. В субботу в 19:00 не отправляется ничего: на воскресенье дежурств нет.

Слово «субботу» само несёт день недели, поэтому суффикс «СБ» в этих сообщениях
не дублируется.

Несколько дежурных перечисляются в одну строку: `format_vk_mentions()` склеивает
упоминания как «A, B и C». На табло они, наоборот, разносятся по строкам — см. §8.

В упоминание уходит «Фамилия Имя»: `get_vk_mention()` прогоняет имя через
`shorten_name()`. Поиск по `vk_users.json` при этом идёт по **полному** ФИО —
ключи там бывают обоих форматов, а `split_duty_names()` опирается на отчества,
когда режет ячейку с несколькими дежурными без запятой. Сокращается только
подпись.

Дедупликация — через `last_notifications` (ключ `тип:дата`), словарь в памяти:
после рестарта в ту же минуту уведомление уйдёт повторно.

Условие срабатывания — **точное совпадение минуты**. Цикл спит 60 секунд, так что
запас нулевой: если итерация сместится, окно можно пропустить. Не увеличивайте
`sleep` не переписав условие на диапазон.

`vk_users.json` — маппинг «ФИО → VK id» для упоминаний. Два формата значения:
`"Иван Иванов": 101` или `"Пётр Петров": {"id": 202, "label": "Пётр"}`. Нет записи —
в сообщение уйдёт голое имя + warning в лог. Файл читается заново на каждое
сообщение и редактируется со страницы `/settings` (§7).

`split_duty_names()` разбивает ячейку на несколько человек: по запятой; если
запятых нет — по отчествам; если и их нет — по парам слов при чётном количестве
слов > 2 («Иванов Иван Петров Пётр» → двое). Эвристика ломается на одиночных
фамилиях — учитывайте при правках.

Все обращения к VK идут через `call_api()`: параметры уходят телом POST, а не в
query string, поэтому токен не оседает в логах прокси. Ретраев нет; ошибка
`messages.send` только логируется, и тогда ключ дедупликации **не**
проставляется, то есть попытка повторится на следующей минуте того же часа.

### Кнопки и команды

К каждому сообщению бота цепляется инлайн-клавиатура «Сегодня / Завтра /
Неделя» (`build_keyboard()`). Нажатия и те же слова текстом ловит второй
фоновый поток — `_commands_loop()` на Bots Long Poll.

| Кнопка | Ответ |
|---|---|
| Сегодня | утро и вечер за сегодня; в субботу — одна смена, в воскресенье прямо об этом |
| Завтра | то же за следующий день |
| Неделя | текущая неделя ПН–СБ, по строке на день |

Почему так сделано:

* **Long Poll, а не Callback API.** Контейнер живёт в локальной сети, публичного
  адреса под вебхук у него нет.
* **Токену нужны права «управление сообществом»**, иначе
  `groups.getLongPollServer` вернёт ошибку и кнопки будут молчать (уведомления
  при этом продолжат ходить). В логе это видно явным сообщением.
* **`groups.setLongPollSettings` вызывается на старте** — без включённого
  `message_new` long poll не присылает ничего. Вызов идемпотентный.
* **id группы определяется сам** через `groups.getById` по токену. `VK_GROUP_ID`
  нужен, только если автоопределение не сработало.
* **Отвечаем только в беседе из `VK_PEER_ID`.** График дежурств — не публичные
  данные, а в личку боту может написать кто угодно.
* **В ответах на команды имён-упоминаний нет**, только текст: иначе каждое
  нажатие кнопки пинговало бы людей. Упоминания остаются в плановых
  уведомлениях.

Выключается одним флагом `VK_COMMANDS_ENABLED` (или галкой в настройках): поток
остаётся, но засыпает, и клавиатура к сообщениям не цепляется.

## 6. Подводные камни (проверено на живом запуске)

1. **`LOG_DIR` по умолчанию = `/app/logs`** — значение для контейнера. На Windows
   `os.makedirs` создаст `C:\app\logs` и будет писать туда. Локально всегда
   передавайте `LOG_DIR=logs`.

2. **`TZ=Asia/Yekaterinburg` из `.env` ломает таймстемпы логов на Windows.**
   `load_dotenv()` кладёт `TZ` в окружение до первого обращения к `time`, CRT
   Windows не понимает IANA-имя и откатывается на UTC — в логе время на 5 часов
   меньше реального. На данные и API это **не** влияет (там `pytz` +
   `SERVER_TIMEZONE`), только на строки лога. В Linux/Docker проблемы нет.

3. **Один worker — жёсткое требование.** Планировщик и VK-нотифаер живут внутри
   процесса приложения; `workers = 1` в
   [gunicorn.conf.py](backend/gunicorn.conf.py:3) обязателен, иначе уведомления
   задублируются по числу воркеров.

4. **Локальный запуск = живые внешние вызовы.** Приложение реально ходит в
   Google Sheets и NTP. Если запускаете рядом со временем 10:00/19:00 — глушите
   VK через пустые `VK_BOT_TOKEN`/`VK_PEER_ID`, иначе в рабочую беседу уйдёт
   тестовое сообщение.

5. **Кракозябры в консоли Windows.** Русский вывод в Git Bash/cmd бьётся из-за
   cp1251. Лечится `PYTHONIOENCODING=utf-8`; на работу приложения не влияет.

6. **Не читайте лист по имени.** У него опечатка («Дежуство») и пробел на конце.
   Обращение к листу — только через `open_duty_worksheet()`.

7. **Пустое табло ≠ поломка.** Если в таблице нет строк на текущие две недели,
   API честно отдаст `weeks` с пустыми ячейками и `today_duty: null`. Лист
   размечен по 07.11.2026 (60 дат), заполнен людьми — по 19.09.2026.

8. **Четверо из графика не сопоставлены с VK id** (Афонин Кирилл Борисович,
   Назаров Михаил Владимирович, Удочкин Сергей Юрьевич, «Юрчик») — в
   уведомлениях они пойдут обычным текстом без упоминания. Лечится в блоке
   «Участники VK» на `/settings`.

9. **`credentials.json`, `.env`, `vk_users.json`, `settings.json` не в git** (см.
   `.gitignore`) и лежат только локально или на сервере. Никогда не коммитьте
   их и не выводите содержимое в логи или ответы.

## 7. Конфигурация

Два источника: переменные окружения (дефолты) и файл настроек, который
перекрывает их поточечно. `load_config(overrides)` собирает из них `AppConfig`.

### Файл настроек и страница `/settings`

Watchtower не читает `docker-compose.yml` и замораживает environment на момент
последнего `docker compose up -d` (§12), поэтому правка `.env` без захода на
сервер ничего не давала. Настройки, заданные через `/settings`, лежат в
`settings.json` (`SETTINGS_FILE`, в контейнере — `/app/data/settings.json` на
именованном томе `duty_settings`) и переживают пересоздание контейнера.

Что редактируется — список `SETTING_FIELDS` в
[settings_store.py](backend/duty_scheduler/settings_store.py). Инфраструктурное
(`LOG_DIR`, `FRONTEND_DIR`, `SETTINGS_FILE`, пути к `credentials.json` и
`vk_users.json`) там намеренно отсутствует: это про то, как контейнер собран, а
не про то, как приложение работает. Содержимое самих `credentials.json` и
`vk_users.json` при этом редактируется — см. ниже.

Применение идёт без перезапуска: `apply_runtime_config()` пересобирает
`AppConfig` и раздаёт его сервисам, а оба фоновых цикла читают `self.config` на
каждой итерации. Смена часового пояса видна в `/api/data` сразу же. После записи
запускается внеочередное обновление таблицы в отдельном потоке.

Аутентификация: пароль задаётся при первом обращении к настройкам и дальше
спрашивается при каждом входе. PBKDF2-HMAC-SHA256 с солью, там же в файле; сессия
— подписанная cookie Flask, ключ подписи тоже в файле (иначе логин не пережил бы
рестарт). Пять неудачных попыток с адреса блокируют его на 5 минут.

Сама страница `/settings` отдаётся без пароля — всё, что она показывает,
приходит из `/api/settings`, а там вход уже проверяется. Вход на табло —
полупрозрачная шестерня в правом верхнем углу.

Токен VK наружу не отдаётся: в форму уходит плейсхолдер `********`, и он же
понимается при сохранении как «секрет не меняли».

### Файлы под управлением страницы: `vk_users.json` и `credentials.json`

Ниже формы — два блока, которые правят не значения, а файлы
([managed_files.py](backend/duty_scheduler/managed_files.py)):

* **Участники VK** — таблица «имя / VK id / подпись». Сохраняется списком
  целиком в `VK_USERS_FILE`; файл создаётся, если его не было. Формат тот же,
  что читает `VkNotifier`: без подписи — `"имя": id`, с подписью — объект.
  Валидация: имя непустое и уникальное без учёта регистра, id — положительное
  число. Применяется мгновенно — нотифаер читает файл на каждое сообщение.
* **Ключ сервисного аккаунта Google** — загрузка JSON-ключа в
  `GOOGLE_CREDENTIALS_FILE`. Принимается только `"type": "service_account"` с
  `client_email`, `private_key`, `token_uri`; файл пишется с правами `0600`.
  Наружу уходит только признак наличия и `client_email` — чтобы было видно,
  кому открывать таблицу. Если ключ уже есть, замена требует явного `replace`
  (на странице — подтверждение). После загрузки запускается внеочередное
  чтение таблицы.

Оба блока показывают, доступен ли файл на запись. В контейнере файлы лежат на
томе `duty_settings` (`/app/data/`, пути захардкожены в `docker-compose.yml`)
рядом с `settings.json`. Старый compose с `:ro`-монтированием с хоста тоже
работает — страница честно скажет, что файл только для чтения.

Первичное наполнение тома на сервере: `deploy.sh` после старта копирует
`credentials.json` и `vk_users.json` из своего каталога в том, **только если
там их ещё нет** — том источник правды, правки с `/settings` не затираются.
Вручную то же самое:

```bash
docker cp credentials.json duty-schedule-app:/app/data/credentials.json
docker exec duty-schedule-app chown appuser:appuser /app/data/credentials.json
```

## 8. Фронтенд

Один класс `DutyScheduleApp` в [app.js](frontend/static/app.js:1), без сборки и
зависимостей — Bootstrap на табло больше не подключается (он остался только на
`/settings`).

* `fetchData()` — опрос `/api/data` раз в 30 с, с флагом `isFetching` против
  наложения запросов и `cache: "no-store"` + `?_=timestamp` против кэша.
* **Время — серверное и в поясе сервера.** Часы идут от `server_time` через
  `performance.now()`, а сдвиг пояса берётся из ISO-строки (`+05:00`).
  `getServerWallClock()` возвращает `Date`, у которого «настенное» время сервера
  лежит в полях `getUTC*()` — пояс браузера ни на что не влияет. «Сегодня»,
  подсветка дня и состояние смен считаются от этих часов, а не от
  `toISOString()` браузера (раньше с 00:00 до 05:00 подсвечивался вчерашний день).
* Время смен (`SHIFTS`: утро 8–10, вечер 17–20, суббота 8–16) — константа во
  фронтенде: в API его нет, а в таблице оно одинаковое для всех дней.
* **Верхний блок** показывает сегодняшние смены, пока хоть одна не закончилась,
  с пометками «сейчас» / «завершено». После последней смены и в день без
  дежурств — ближайший день с дежурством («Завтра», «Понедельник, 5 октября»).
  `today_duty` из API фронтенд больше не читает — всё берётся из `weeks`.
* **Сетка** — CSS Grid: колонка подписей смен + 6 дней, каждый день — `subgrid`
  на три строки (заголовок, утро, вечер), суббота занимает обе строки смен.
  Прошедшие дни приглушены, сегодняшний выделен. Имя разбито на фамилию и имя
  двумя строками: так крупный шрифт влезает в колонку.
* **Размеры в `rem`, `rem` привязан к экрану**: `html.board-root` получает
  `font-size: min(1.0417vw, 1.852vh)` = 20px на 1920×1080. Табло одинаково
  заполняет экран любого разрешения; класс стоит только на табло, чтобы не
  задеть `/settings` с его Bootstrap.
* **Рендер без перестройки.** Сетка строится DOM-методами (`textContent`, без
  `innerHTML` с данными) и перестраивается только при смене окна дат или дня.
  Иначе `updateDay()` обновляет лишь ячейки, где поменялись люди, и вешает на
  них класс `is-changed` — хук для анимации. Верхний блок сравнивается по ключу
  и перерисовывается только при изменении (проверка раз в минуту).
* **Ошибки не стирают табло.** Непустой `error` при непустом кэше
  (`last_updated`) значит, что не прошло последнее обновление, а старые данные
  верны: сетка остаётся, строка состояния внизу справа становится жёлтой
  («Таблица не обновляется · данные от …», текст ошибки — в `title`). Сбой
  самого `fetch` — красная строка, сетка тоже остаётся. Сообщение вместо сетки
  — только если данных ещё не было ни разу.
* Фон — отдельно, в `backgrounds.css` / `backgrounds.js`, см. ниже.
* Выходные рендерятся особым путём: для СБ/ВС показывается только `evening`,
  одним слотом на обе строки смен.
* Несколько дежурных в одной ячейке (суббота) разносятся по строкам:
  `splitPersons()` режет строку по запятой. В VK-уведомлениях, наоборот,
  перечисление в одну строку — см. §5.

### Оформление и шрифт

Стиль — «стекло»: полупрозрачные панели с размытием поверх анимированного
фона. Цвета, радиусы и подсветки — токены в `html.board-root` в начале блока
табло в [style.css](frontend/static/style.css); правьте их, а не отдельные
правила.

Шрифт — **Onest** (вариативный, 100–900, OFL), лежит локально в
`frontend/static/fonts/`: табло в локальной сети не должно зависеть от CDN.
Взяты только подмножества cyrillic и latin (~50 КБ) из
`@fontsource-variable/onest` 5.3.1, с их `unicode-range`. Подключён через
`--font-ui` на `body` — действует и на `/settings`. Цифры в часах и датах —
`font-variant-numeric: tabular-nums` (`tnum` в шрифте есть), иначе часы
«дрожат» каждую секунду.

### Анимированный фон

[backgrounds.css](frontend/static/backgrounds.css) и
[backgrounds.js](frontend/static/backgrounds.js), подключаются только на табло.

* **Подложка** `.background-animation`: «небо» `.background-sky` (цвет по
  времени суток, см. ниже), блики в `::before` медленно плывут через
  `transform`, затемнение в `::after`.
* **Две сцены** `.background-scene`. `BackgroundController` ставит пресет в
  скрытую сцену (класс `bg-<имя>`, при нужде — пустые `<span>`), проявляет её
  и растворяет видимую. Кроссфейд — `opacity` за `BACKGROUND_FADE_MS` (6 с),
  смена — раз в `BACKGROUND_INTERVAL_MS` (2 мин), следующий пресет случайный,
  но не тот же. Уходящая сцена после перехода **очищается**: скрытый слой
  ничего не рисует и не крутит анимаций (раньше предзагруженный слой всё
  время анимировался невидимым).
* **Пресеты** — `BACKGROUND_PRESETS` в JS + класс в CSS. Все четыре — порты
  `animations_examples/` с сохранением геометрии, цвет — `--bg-line` (светлый
  тон табло), темп замедлен в 2–5 раз:

  | Пресет | Пример | Как устроен |
  |---|---|---|
  | `orbs` | cssbackgroundanimation | 5 концентрических кругов у левого края, `scale` с нарастающей задержкой — волна |
  | `angled` | css-only-animated-angled-pattern | Шевроны; полосы едут навстречу. Два псевдоэлемента с взаимодополняющими масками, сдвиг на тайл через `transform` |
  | `octagons` | square-vs-octagon | `@property` (`--oct-a/p/c1/c2`) морфит восьмиугольники в квадраты, в середине цикла цвета меняются местами |
  | `mosaic` | no-divs-background-pattern-animation | 4 слоя квадратиков переставляются рывками с паузами; круглые «окна» исходника сделаны маской |

  Собственные пресеты — тоже только `transform`/`opacity`:

  | Пресет | Как устроен |
  |---|---|
  | `aurora` | 4 больших мягких пятна разных оттенков дрейфуют и смешиваются через `mix-blend-mode: screen` |
  | `waves` | 3 слоя волн у нижнего края (периодический SVG-путь в data URI), разные длины, скорости и направления |
  | `stripes` | Мягкие диагональные полосы в одну сторону и тонкие линии в другую; сдвиг на период × √2 бесшовен |
  | `bokeh` | 22 размытых огонька всплывают снизу; позиции, размеры и скорости случайные — `setup` в JS |

  Подводные камни портов: в `angled` и `octagons` исходники рассчитаны на
  **непрозрачные** цвета (верхний слой перекрывает нижний, фигуры —
  подложку). У нас узор полупрозрачный, поэтому `angled` делит экран двумя
  масками, а `octagons` рисуется двумя сплошными цветами на `::before` с
  `opacity`. Прозрачность самой сцены трогать нельзя — она занята
  кроссфейдом.
* **Цвет по времени суток.** В `.background-sky` четыре слоя с градиентом
  подложки: утро 8–12 (рассвет: индиго, лаванда, персиковые края), день 12–16
  (исходная синяя палитра), вечер 16–20 (закат: фиолетовый, пурпур, розовые
  края), ночь 20–8 (глубокий тёмно-синий). `setDaypart()` вызывается из часов
  табло раз в минуту по **серверному** времени. Смена — `showSky()`: новый
  слой за `SKY_FADE_MS` (10 мин) проявляется **поверх** старого, а старый
  (`is-previous`) остаётся под ним непрозрачным и гаснет только по
  `transitionend` — так цвет перетекает без провала яркости посередине, и
  только через `opacity`, без перерисовки экрана. Слой лежит под бликами и
  сценами за счёт `z-index: -1` внутри контекста наложения подложки. При
  загрузке цвет ставится сразу, без перехода. Узоры пресетов цвет не
  меняют — они светлые полупрозрачные и ложатся на любое небо.
* **Отладка:** `?bg=angled` или `?bg=angled,mosaic` — ограничить набор,
  `?bgInterval=15` — менять раз в 15 с, клавиша **B** — следующий пресет,
  `?daypart=evening` — зафиксировать часть суток, клавиша **D** — следующая
  часть суток, `?skyFade=10` — перетекать за 10 с вместо 10 минут.
* Переходы между пресетами — только плавный кроссфейд. Шторки, жалюзи,
  раскрытия через `clip-path` сознательно не используются: смена фона не
  должна бросаться в глаза.
* Новый пресет = запись в `BACKGROUND_PRESETS` (`layers`, при случайных
  параметрах — `setup`) + блок `.bg-<имя>` в CSS.
  Движение — по возможности через `transform`/`opacity`; анимация
  `background-position`/`background-size` перерисовывает весь экран на
  каждом кадре, а поверх лежат панели с `backdrop-filter`.

В правом верхнем углу — ссылка `.settings-link` на `/settings`: шестерня с
`opacity: 0.12`, на телевизоре её практически не видно. `body` на табло скрывает
курсор, а шестерня возвращает `cursor: pointer` — так её находят мышью.

`SETTING_FIELDS`, оно само появилось в интерфейсе. Блоки «Участники VK» и
«Ключ Google» — статичная разметка в `settings.html` (`#files-section`),
показывается вместе с формой после входа; список участников рендерится
DOM-методами, без `innerHTML` с данными. Загрузка ключа — `FormData`, поэтому
`request()` не ставит JSON-заголовок для multipart-тела.

`settings.css` подключается **после** `style.css` и переопределяет ровно то, что
в нём заточено под киоск: прокрутку и скрытый курсор. `overflow` там именно
`visible`, а не `auto`: любое не-`visible` значение делает скроллером сам `body`,
со своей полосой прокрутки поверх страницы. Анимированных слоёв фона на форме
нет намеренно — страницу открывают и подолгу держат.

## 10. Рабочие соглашения

* Стиль: type hints, `from __future__ import annotations` в модулях с `|`-юнионами,
  f-строки в логах, никаких сторонних линтеров/форматтеров в проекте нет.
* Новые HTTP-ручки — в `api.py` (или `settings_api.py`, если про настройки),
  доступ к сервису через `current_app.extensions["schedule_service"]`, а не
  через глобалы.
* Новая настройка = запись в `SETTING_FIELDS` + ключ в `values` внутри
  `load_config()`. Поле формы, валидация и хранение появятся сами; поле, которого
  нет в `load_config()`, молча не применится.
* Любое обращение к `data_cache` — только под `cache_lock`.
* Порядок правок при изменении формы данных: `schedule_service.build_api_payload()`
  → `backend/tests/test_schedule_service.py` → `frontend/static/app.js::processData`
  → бамп `app_version`.
* Изменилась разметка листа — правьте `parse_duty_sheet()` и фикстуру
  `duty_sheet_fixture()`, а не отдельные номера колонок по коду.
* Пуш в `main` может собрать и опубликовать образ — см. §11. Если собрал,
  watchtower на сервере подхватит его в течение ~2 минут, то есть коммит в
  `main` фактически равен деплою в прод.

## 11. CI/CD и условная сборка

[docker.yml](.github/workflows/docker.yml) состоит из двух job'ов.

**`changes`** сравнивает `github.event.before` с текущим коммитом и решает,
затронут ли образ:

| Изменилось | Пересборка |
|---|---|
| `backend/**` | да |
| `frontend/**` | да |
| `Dockerfile`, `.dockerignore`, сам `docker.yml` | да |
| `*.md`, `animations_examples/**`, `deploy.sh`, `docker-compose.yml` | **нет** |

`deploy.sh` и `docker-compose.yml` в образ не попадают, поэтому их правки
сборку не требуют — они применяются на сервере через `docker compose up -d`.

**`docker`** выполняется только при `needs.changes.outputs.build == 'true'` и
делает то же, что и раньше: buildx → login → metadata → build-push.

Почему фильтр в отдельной job, а не в `on.push.paths`: `paths` применяется и к
пушу тегов, из-за чего релизный тег на «документационном» коммите мог бы
молча не собраться. В job'е тег обрабатывается явно — **тег собирается всегда**.
Так же обрабатываются первый пуш и force-push, где базовый коммит недоступен:
собираем, а не пропускаем.

Что фильтр НЕ делает: `backend/tests/**` считается изменением бэкенда, хотя
тесты в образ не попадают. Сделано намеренно — предсказуемость важнее экономии
одной сборки. Если захотите исключить, это одна строка в шаге
`Detect changed components`.

Результат решения пишется в summary запуска — видно, какая зона изменилась и
собирался ли образ.

Оба компонента едут в одном образе (Flask сам отдает статику), поэтому раздельной
сборки frontend/backend нет. Выходы `changes.outputs.backend` и `.frontend`
существуют именно на случай, если фронтенд когда-нибудь поедет отдельно.

## 12. Секреты

Правило простое: **секреты сборки — в GitHub Secrets, секреты рантайма — на
сервере**.

* `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN` — GitHub Secrets, нужны только CI.
* `.env` — только на сервере, читается compose'ом.
* `settings.json`, `credentials.json`, `vk_users.json` — на именованном томе
  `duty_settings` (`/app/data`), пишутся самим приложением через `/settings`
  (§7). `settings.json` содержит хеш пароля, ключ подписи сессий и токен VK.
  В git не попадают (`.gitignore` ловит их правилом `*.json`), в образ — тоже
  (`.dockerignore`).

Ни один из них никогда не попадал в git (проверено `git log --all` по каждому
пути) и не попадает в образ: [.dockerignore](.dockerignore) отсекает
`credentials.json`, `.env*`, `*.pem`, `*.key`, а [Dockerfile](Dockerfile)
копирует только `backend/` и `frontend/`.

**Никогда не запекайте секреты в образ.** Репозиторий `koroserg/duty-schedule`
на Docker Hub **публичный** — образ может скачать и распаковать кто угодно.
GitHub Secrets доступны только во время сборки, до рантайма на сервере они не
доходят в принципе, поэтому «перенести credentials.json в секреты GitHub»
technически означало бы «опубликовать ключ».

### Watchtower и переменные окружения

Watchtower не читает `docker-compose.yml`. Он забирает новый образ и пересоздает
контейнер, копируя конфиг со старого. Отсюда:

* **именованные тома** (`duty_settings`, `duty_logs`) переезжают в новый
  контейнер как есть;
* **переменные окружения замораживаются** на значениях последнего
  `docker compose up -d`. Правка `.env` сама по себе не применится.

Добавили или изменили переменную в `docker-compose.yml`/`.env` — нужен
`docker compose up -d` на сервере, watchtower этого не сделает. Ровно поэтому
появилась страница настроек: значение, заданное там, лежит на томе и
пересоздание контейнера переживает (§7).

Том `duty_settings` подключается через `docker-compose.yml`, так что **первый**
переезд на эту версию требует одного `docker compose up -d` на сервере —
watchtower сам том не добавит.

Осознанно не сделано и требует ручной проверки на сервере:

* **Long poll вживую не проверялся** — нужен рабочий групповой токен, а он
  только на сервере. Если у токена нет прав «управление сообществом», кнопки
  будут молчать, а в логе появится явное сообщение; уведомления при этом
  продолжат ходить как раньше.
* **Образ локально не собирался** — Docker на машине разработки отсутствует.
  Проверялись пути, локальный запуск, страница настроек в браузере и тесты.
* **Первый деплой требует `docker compose up -d` на сервере**: watchtower не
  добавит том `duty_settings` сам (§12). Bind-mount'ов `credentials.json` и
  `vk_users.json` в compose больше нет — после `up -d` их надо один раз
  положить в том: `./deploy.sh` делает это сам, либо `docker cp` (§7), либо
  загрузка через `/settings`. Пока ключа нет, `/api/data` отдаёт ошибку.
* `.env` не тронут: env остаётся источником дефолтов, и всё продолжает
  работать до того, как в настройках что-то зададут.
